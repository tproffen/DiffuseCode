Test coverage gaps – what to add and harden#

Part of WP0 (WP0_Test_Baseline.md) of the migration plan. This compares the commands documented in the help files with what the current macro tests actually run and check. It then lists the tests to add or strengthen, ordered by when the migration work packages (WP3–WP9) need them. mixscat is deprecated and not included.

Generated from the run of 2026-11-13 (claude-python-app after PR #33; 31 tests). Re-run at any time:

python3 tools/run_legacy_tests.py --exe /path/to/discus_suite -j 4 --workdir /tmp/run

python3 tools/command_coverage.py --logs /tmp/run --markdown coverage.md

Reached is not the same as checked. Many tests run a command but only check something simple afterwards. Section 3 rates each test’s check.

How the numbers are made, and their limits:

  • Commands come from the help files: level 2 is a command, level 3 is a sub-command or option.

  • What ran comes from the command echo in the test logs, matched by unique prefix, since the command language accepts abbreviations.

  • Macro echo also prints the lines of if branches that are not taken. Commands inside do loops in a sub-menu are echoed with the outer prompt. A few counts can therefore be off; for example, transform counts as reached because a trans … line inside a menu loop matched it.

  • Options passed as parameters (for example set technique:nufft) are only counted for set. Everything else is counted at command level.

Command language and suite#

The command language is being retired, so test only what macros still depend on. if, do, variable, fopen, fput and similar are already covered as a side effect. Exceptions:

  • seed: needed for reproducible tests (0.5a).

  • Error handling: no test checks that a bad command gives the expected error. WP2 maps errors to Python exceptions, so a small set of “this input must fail with error N” tests is worth having.

4.4 Out of scope (decide once, then document)#

  • KUPLOT plot styling (colours, fonts, frames, titles, marks): replaced by matplotlib/plotly, so not worth testing.

  • Command-language features not used by any macro (learn, mount, fsub, timer, sockets): retire rather than test.

  • mixscat: deprecated.

  • EXPERI: test only if it is still used.

5. Conventions for new tests#

  • One feature per macro, small crystal, run time under 10 s.

  • seed at the start of every stochastic test (once 0.5a is fixed).

  • Compare against stored reference data (RESULTS/ now, golden/ from task 0.6), not only against counts or ranges.

  • Plot macros use program cif and run, never program jmol or run plot:inter.

  • Add every test to test_all.mac and manifest.toml together. Tag it (fast, mc, …), and check with tools/run_legacy_tests.py --check-test-all.

  • After adding tests, re-run tools/command_coverage.py and update the appendix below.
